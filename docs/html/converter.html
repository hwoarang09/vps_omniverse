개요

converter/ 는 VPS 의 AMHS 맵(input/fab_map/*.map)을 OpenUSD 로 바꾸는 빌드타임 스크립트 묶음이다. 컴파일러에 가깝고 앱 런타임이 아니다 — Omniverse 없이 순수 usd-core(pxr)로 돈다. 실행 파이썬은 /home/vosui/vosui/omniverse_test/.venv/bin/python, 항상 converter/ 안에서 실행한다.

VPS(Three.js)에서 InstancedMesh.setMatrixAt 로 그리던 레일/스테이션을, 여기서는 UsdGeom.PointInstancer 한 개로 옮긴다. 입력 파싱 로직은 VPS 그대로 번역하고 (mapio.py:1-9) 출력만 USD 로 교체한 구조다.

이 문서는 빌드타임 변환기만 다룬다. 여기서 만든 두 레이어를 USD 합성(LIVRPS)으로 쌓는 이야기는 usd-composition, 런타임에서 MQTT 로 VPS 데이터를 받아 차량을 움직이는 이야기는 runtime 문서로 분리되어 있다.

  • base.usda raw 2줄 레일 + 스테이션/장비/바닥/카메라 — 아무것도 안 가린 원본
  • line_cut.usda over /World/Rails { invisibleIds } — 겹침 세그먼트만 비파괴 숨김
  • composed.usda subLayers=[line_cut, base] 정적 stitch (손으로 쓴 파일, 코드가 생성 안 함)

파싱 → 기하/hide 계산 → USD prim 작성 → 두 레이어 출력. 합성은 정적 composed.usda 한 줄짜리 stitch.

기하 & 숨김 계산 (geometry.py)

각 edge 중심선을 좌우 ±gauge/2(RAIL_GAUGE=0.4, geometry.py:272) 만큼 오프셋해 2줄 레일로 만들고, RAIL_DRAW_MAXLEN=0.5(geometry.py:360) 간격 박스 세그먼트로 잘라 인스턴싱한다. 박스 클래스(디버그 색)는 green=직선 edge, pink=곡선의 직선구간(lead), red=호(arc) (geometry.py:371-374).

dual_rail_segments_tagged — 모든 세그먼트

dual_rail_segments_tagged(geometry.py:790)는 아무것도 가리지 않은 모든 레일 박스를 만든다. 각 원소는 (pos, yaw, scale, cls, edge_name, side, tmid) 로, 뒤 3개 메타(edge_name / side(L·R) / tmid(중점 정규화 t))가 hide 매칭의 키가 된다(geometry.py:792-793).

대응하는 그리기용 함수 dual_rail_segments(geometry.py:711)는 hide 인터벌을 받아 빼고 그리지만, 레이어 합성에서는 이걸 쓰지 않는다 — base 가 전부 들고 있어야 하기 때문(geometry.py:782-789 주석).

hide 함수 한눈에

hide 는 {edge_name: (left_intervals, right_intervals)} 형태의 정규화 t 인터벌 딕셔너리다. 단계별 함수가 각자 인터벌을 만들고 merge_hide 로 합친다.

함수 (정의)대상하는 일
hide_curve_arc (geometry.py:491)곡선 호(arc) outer 레일 호가 분기(outdeg≥2)/합류(indeg≥2) 끝에 붙으면, 그 끝에서 호 길이의 arc_hide=0.7 (geometry.py:459) 비율을 바깥 레일에서 숨김. 180은 apex 에서 반쪽 2개로 쪼갬(geometry.py:516-519).
hide_curve_lead (geometry.py:551)곡선의 직선구간(lead-in/out) 그 직선부 레일이 이웃 통로 중심선 corridor(±gauge/2) 안에 들고 사잇각 > RAIL_CROSS_ANGLE=30°(geometry.py:540)면 "가로막음"으로 보고 숨김. 나란한 겹침은 보존.
hide_curve_edges (geometry.py:703)곡선 통합(Stage 2) merge_hide(hide_curve_arc, hide_curve_lead) — 곡선 trim 묶음.
hide_linear_edges (geometry.py:666)직선(LINEAR) 안쪽 레일(Stage 3) 분기/합류하는 곡선 기준 노드에서 K×radius 길이만큼 안쪽 레일 1줄을 끊음(아래 5.1).
merge_hide (geometry.py:690)딕셔너리 병합 여러 {edge:(L,R)} 를 edge별 좌/우 인터벌 union 으로 합침(_merge_intervals).
hidden_seg_indices (geometry.py:826)인덱스 산출 tagged 세그먼트 중 중점 tmid 가 (side 에 맞는) hide 인터벌에 걸리는 것의 인덱스 리스트.

build_line_cut.py:28-31 의 실제 조합: merge_hide(hide_curve_edges(...), hide_linear_edges(...)) → hidden_seg_indices(tagged, hide). 경계는 박스 단위가 아니라 _keep_subsegs(geometry.py:765) 로 소수점 t 까지 정확히 잘린다.

라인끊기 케이스

겹침이 생기는 곳은 분기/합류 정점 주변이다. 아래 그림들은 실제 좌표를 geo.dual_rail_segments_tagged + hidden_seg_indices 로 그대로 뽑아 그린 것이다 (지어낸 그림 아님, docs/html/assets/_plot_linecut.py). 각 그림은 두 장: 왼쪽 = line_cut 적용 전(raw 2줄 전부, 회색), 오른쪽 = 적용 후(invisibleIds 로 가려진 세그먼트가 사라진 모습 — 겹침이 정리된 실제 결과). 점선 = edge 중심선.

직선 라인끊기 (hide_linear_edges)

직선 edge 가 분기/합류 곡선과 만나는 노드에서, 안쪽 레일 1줄을 K×radius 길이만큼 끊는다. K 는 곡선 타입별 계수 RAIL_LINE_CUT_K(geometry.py:600, 현재 전부 2.0)이고, 끊는 t 길이는 K×radius / 직선길이 로 역산한다(geometry.py:681-684).

방향매칭(직선 fn=분기 / tn=합류)·안쪽 레일(L/R)·반경·곡선타입은 _line90_matches(geometry.py:623)가 기하로 자동 판정한다. 안쪽 레일은 그 노드쪽 "호 중점"이 직선의 어느 편인지(world cross)로 정한다 (geometry.py:650-659) — far-node 로 하면 S 에서 반대쪽이 잡히기 때문. 아래 모든 케이스 그림의 '적용 후' 패널에서 이 직선 라인끊기(노드에서 뻗는 직선 안쪽 레일이 사라진 구간)를 함께 볼 수 있다.

CURVE_90 — 분기/합류 90° 곡선

그림 2. CURVE_90 (E0606) — 호 outer 레일 trim(hide_curve_arc) + 직선 안쪽 레일 라인끊기(hide_linear_edges).

CURVE_180 — U턴

180° 단일 호는 apex(중점)에서 반쪽 2개로 쪼개 CSC 처럼 fn/tn 반쪽씩 처리한다 — 양끝 겹침은 지우되 apex 는 보존(geometry.py:516-519, 499-500).

그림 3. CURVE_180 (E0726) — U턴 호 outer trim(apex 보존) + 직선 안쪽 레일 라인끊기.

CURVE_CSC — 곡선-직선-곡선

CSC 는 호가 2개(fn 쪽·tn 쪽)다. 각 호가 자기 가까운 끝의 분기/합류 여부를 따로 보고 바깥 레일을 arc_hide=0.7 비율로 trim 한다(geometry.py:497, 522-533).

그림 4. CURVE_CSC (E0203) — 호 2개 각각 outer trim + 직선 안쪽 레일 라인끊기.

S_CURVE — S자 곡선

S_CURVE 는 호 2개가 서로 반대 방향으로 휜다 → 바깥 레일이 호마다 다른 쪽(L↔R)이 된다. 호가 작아 비율 대신 통째(frac=1.0)로 처리한다(geometry.py:521-527).

그림 5. S_CURVE (E0548) — 호별 반대방향 outer trim + 직선 안쪽 레일 라인끊기.

base / line_cut 인덱스 정합 & 검증

1:1 정렬이 성립하는 이유

make_instancer 는 인스턴스 ids 를 따로 박지 않는다 → instance id = 배열 인덱스 (build_line_cut.py:11-13). base 의 /World/Rails PointInstancer 는 dual_rail_segments_tagged 순서대로 채워지고(build_base.py:92-96), line_cut 의 invisibleIds 도 같은 함수·같은 순서로 만든 인덱스다 (build_line_cut.py:28-39). 그래서 두 레이어 인덱스가 어긋나지 않는다.

  • base: make_instancer("/World/Rails", ... positions=[s[0] for s in rsegs]) (build_base.py:92)
  • line_cut: OverridePrim("/World/Rails") + CreateInvisibleIdsAttr(Vt.Int64Array(hidden)) (build_line_cut.py:38-39)
