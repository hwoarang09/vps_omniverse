이 문서의 목적

OpenUSD 개념을 vps_omniverse 에서 실제로 쓴 자리와 묶어 정리한다. 개념 설명은 일반론이지만, "이 프로젝트 사용처" 는 전부 코드/문서에 근거해 파일:라인 으로 인용한다. 추측한 부분은 "미확인" 으로 표시한다.

독자는 이 프로젝트 개발자(VPS/Three.js 경험 보유). 그래서 가능한 곳마다 Three.js 개념과 대조한다. 이 대조는 converter/usd_build.py 주석의 멘탈 모델 매핑(예: PointInstancer = InstancedMesh)을 그대로 가져온 것이다.

Layer / SubLayer / Composition

USD 의 핵심은 "여러 파일(Layer)의 의견을 정해진 강도 순서로 합쳐 최종 씬을 만든다" 는 것이다. 이 프로젝트는 레일 겹침 정리를 코드로 지우는 대신, 이 합성 메커니즘으로 해결했다.

Layer 란

Layer = USD 데이터의 직렬화 단위. 텍스트 포맷 .usda, 바이너리 .usdc. 이 프로젝트는 학습/디버깅 편의로 전부 .usda(사람이 읽는 텍스트) 를 쓴다.

레이어역할생성
base.usdaraw 2줄 레일 + 스테이션/바닥/조명/카메라 — 지오메트리 원본(전부 def)build_base.py
line_cut.usdaover /World/Rails { invisibleIds } — 겹침 세그먼트 비파괴 숨김build_line_cut.py
composed.usdasubLayers=[line_cut, base] 정적 stitch — 여는 건 이것수작성(맵과 무관)

SubLayer 와 강도 순서

루트 레이어 composed.usda 가 subLayers 로 두 레이어를 쌓는다. 리스트에서 위에 있을수록 강하다. 그래서 같은 prim·속성에 둘 다 의견이 있으면 위(line_cut) 가 이긴다. base 의 지오메트리는 line_cut 에 동일 속성 의견이 없으므로 그대로 통과한다.

#usda 1.0
(
    subLayers = [
        @./line_cut.usda@,   # 강(强) — invisibleIds 권위
        @./base.usda@        # 약(弱) — positions 등 지오메트리 권위
    ]
    upAxis = "Z"
)

근거: out/composed.usda:6-9. line_cut 줄을 지우면 raw 2줄로 복귀 — 합성만으로 보이기/숨김이 바뀐다.

LIVRPS — 합성 강도 순서

한 prim 에 여러 composition arc 의 의견이 모이면 USD 는 정해진 우선순위로 푼다. 머리글자 LIVRPS = Local · Inherits · VariantSets · References · Payloads · Specializes. 앞일수록 강하다.

약자arc한 줄이 프로젝트
LLocal(SubLayers)같은 레이어 스택 내 직접 의견. 위 레이어가 강.사용 composed subLayers
IInheritsclass 로부터 상속.미사용
VVariantSets선택된 variant 의 의견.사용 railColor
RReferences외부 prim/레이어 참조.미사용
PPayloads지연 로드 가능한 무거운 참조.미사용
SSpecializes가장 약한 폴백 의견.미사용

이 프로젝트는 L(SubLayers)과 V(VariantSets)만 쓴다. 핵심은 "line_cut 이 base 보다 위에 있어 강하다" 는 Local 강도 규칙 하나로 겹침 정리가 성립한다는 점이다. 아래 그림이 그 강도 관계다.

VPS 와 대조

VPS(Three.js)에선 겹치는 레일을 정리하려면 자바스크립트에서 배열을 직접 필터링해 메시를 다시 만들어야 한다(파괴적). USD 는 원본(base)을 두고 별도 파일(line_cut)이 "이것만 숨겨" 라고 선언만 한다 — 코드가 아니라 데이터 합성으로 처리한다.

def vs over — 비파괴 오버라이드

prim 스펙의 specifier 가 그 의견의 성격을 정한다.

specifier의미이 프로젝트
defprim 을 정의(생성). 타입·자식·속성을 만든다.base.usda 의 모든 지오메트리
over기존 prim 에 의견만 덧칠. 없으면 아무 것도 안 만듦.line_cut 의 /World/Rails
class상속용 추상 prim.미사용

line_cut 의 over

line_cut 은 OverridePrim("/World/Rails") 로 over 스펙을 만들고, 거기에 invisibleIds 속성 하나만 적는다. base 에 이미 정의된 /World/Rails PointInstancer 위에 "이 인덱스들은 숨겨" 라는 의견만 덧칠하는 것이다 — base 파일은 손도 안 댄다.

# build_line_cut.py:38-39
over = lc.OverridePrim("/World/Rails")              # 'over' specifier(비파괴)
UsdGeom.PointInstancer(over).CreateInvisibleIdsAttr(Vt.Int64Array(hidden))

근거: converter/build_line_cut.py:38-39. invisibleIds 의 인덱스가 base PointInstancer 의 인스턴스 순서와 1:1 이어야 맞는데, 양쪽 다 geo.dual_rail_segments_tagged 를 같은 순서로 돌려 정렬을 보장한다(build_line_cut.py:11-13, 28).

비파괴의 의미

  • base 는 raw 2줄을 전부 유지 — 원본 데이터 손실 없음.
  • 숨김은 line_cut 의 invisibleIds 한 속성에 격리.
  • line_cut 의 invisibleIds 를 비우면 즉시 raw 2줄로 복귀(build_line_cut.py:45).

Prim / Attribute / PointInstancer

Prim 은 씬 그래프 노드, Attribute 는 그 위의 타입 있는 값. PointInstancer 는 prototype 을 대량 인스턴싱하는 prim 타입으로, Three.js 의 InstancedMesh 와 1:1 대응한다.

PointInstancer 의 protoIndex

PointInstancer 는 prototypes(relationship)로 prototype prim 들을 가리키고, 인스턴스마다 protoIndices[i] 로 "이 인스턴스는 몇 번 prototype" 인지 고른다. positions/orientations/scales 로 각 인스턴스를 변형한다.

속성역할Three.js 대응
prototypesprototype prim 경로 목록(rel)geometry/material 풀
protoIndices인스턴스별 prototype 선택 인덱스(InstancedMesh 엔 직접 대응 없음)
positions인스턴스 위치setMatrixAt 의 위치
orientations인스턴스 회전(quat)setMatrixAt 의 회전
invisibleIds숨길 인스턴스 인덱스해당 인스턴스 스킵

레일 — protoIndex 로 타입별 색

레일은 단위 큐브 prototype 을 레일 타입 키(RAIL_DEBUG_KEYS)마다 1개씩 두고, 세그먼트마다 proto_indices 로 자기 타입 prototype 을 가리킨다.

                  orientations=[ub.quat_yaw_rad(s[1]) for s in rsegs],
                  scales=[Gf.Vec3f(*s[2]) for s in rsegs],
                  proto_indices=[rail_key_to_idx[s[3]] for s in rsegs])

VariantSet — 레일색 토글

VariantSet 은 한 prim 에 "교체 가능한 의견 묶음" 을 달아 런타임에 선택만 바꾸는 메커니즘이다. LIVRPS 의 V 위치라 Local(SubLayers) 다음으로 강하다.

빌드타임 author

converter 가 /World/Protos prim 에 railColor variantSet 을 굽는다. variant realistic/debug 각각의 edit context 안에서 prototype 의 머티리얼 바인딩을 다르게 author 하고, 기본은 realistic 로 둔다.

Stage · usdview · .usda

Stage

Stage 는 루트 레이어를 열어 composition(LIVRPS)을 모두 푼 최종 씬 그래프 뷰다. 파일(Layer)이 디스크의 의견이라면 Stage 는 그것들을 합친 "지금 보이는 결과". 빌드타임엔 Usd.Stage.CreateNew(usd_build.py:17, build_line_cut.py:37), 런타임엔 omni.usd.get_context().get_stage()(extension.py:81)로 얻는다.

.usda 는 사람이 읽는 텍스트 포맷이라 합성 전 각 레이어의 의견을 눈으로 확인할 수 있다. composed.usda 는 단 12줄 남짓의 stitch 파일이고, 실제 데이터는 subLayers 가 들고 있다.
